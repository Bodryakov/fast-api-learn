Техническое задание на создание проекта Fast-API-Learn с готовой базой и структурой

Задача.
Создай full-stack web-приложение представляющее собой сайт учебного курса для обучения студентов основам фреймворка Fast-API.

Применяемый стек технологий.
Backend web приложения должен быть на Fast-API с подключением к Supabase.
Тексты уроков и другая информация должна хранится в базе данных Supabase в формате JSONB.
Frontend должен быть на чистом HTML, CSS, VanillaJS, без каких либо дополнительных фреймворков.
Должен подключаться редактор уроков Tiptap.
Структура проекта должна быть минимальна с минимальным (насколько это возможно в данном стеке) количеством файлов и подкаталогов.
Всё должно быть просто и минимально.
Web-приложение должно быть подготовлено к деплою на koyeb.com.

Общее содержание и функционал сайта
Сайт должен выглядеть как последовательность уроков разбитых на разделы. (Для образца сделай 2 раздела по два урока). 
Количество, порядок, названия разделов и уроков определяет админ. (примерно 5 разделов и 10 уроков в каждом разделе). 
Структура URL должна быть примерно такая: 
section-<section_number>-<section_name>/lesson-<lesson_number>-<lesson_name>
Отдельной Главной страницы не нужно. При заходе на сайт пользователь должен сразу попадать на страницу разделов и уроков (оформленных визуально как карточки).
Заголовок карточки раздела должен быть кликабельным и вести на страницу данного раздела, на которой должны быть карточки уроков с кликабельными заголовками ведущие на страницу этого урока. Внутри карточки раздела должны быть кликабельные заголовки уроков ведущие на страницу соответствующего урока.
HTML-страницы каждого урока должны формироваться динамически, при клике на заголовок или гиперссылку соответствующего урока соединяя единый шаблон урока и данные (учебный материал) полученный в формате JSON из базы данных.
Добавление уроков должно быть похоже на добавление постов в блоге и осуществляться в редакторе Tiptap в админ-панели.
Нужно предусмотреть отдельную страницу 404/ошибки с кнопкой перехода на главную страницу.

Описание урока
Каждый урок должен состоять из 
1. теоретического материала, 
2. тестирования, 
3. задач. 
Тесты должны быть простого типа: вопрос, 4 варианта ответа из которых только один правильный. Количество тестовых вопросов админ должен определять сам для каждого урока. (для образца сделай по четыре тестовых вопроса в каждом уроке).
После каждого ответа - правильный ответ должен подсвечиваться зелёной галочкой с зелёной обводкой, а неправильный - красным крестиком с красной обводкой.
Прогресс и результаты прохождение тестов сохранять не нужно.
Статистика по пользователям (кто какие уроки прошел) не нужна.
Для задач интерактивный редактор с проверкой кода не нужен. Должно быть только условие задачи.
В конце каждого урока должны быть кнопки предыдущий/следующий/в оглавление, но только в рамках данного раздела. В последнем уроке раздела, должна быть кнопка перехода на главную страницу.
Все данные урока, включая используемые в тексте изображения, хранятся в формате JSONB в базе данных Supabase.
Каждому уроку должна соответствовать отдельная HTML-страница.

Описание редактора
Для создания и редактирования уроков должен быть текстовый редактор Tiptap с возможностью выбора шрифта, цвета, и других параметров текста для содержимого уроков. При редактировании текста урока не должно быть необходимости использовать HTML-тэги. Все возможности редактирования должны быть обеспечены инструментами текстового редактора. Также нужна  возможность добавления таблиц, списков, ссылок, изображений в текст уроков. 
Форматы изображений: png, jpg, webp, svg. Для поддержки форматов изображений используй необходимые библиотеки. Нужна возможность загрузки файлов изображений через редактор Tiptap и сохранения их в Supabase Storage, а также путей к файлам изображений в базе данных в записи соответствующего урока. Предварительный просмотр загруженных изображений Не нужен. Ограничения на размер загружаемых файлов: максимум 5 МБ для изображений. Сжатие/оптимизация изображений не требуется.
Должна быть подсветка кода отдельно для кода на:
Python,
fastAPI,
HTML,
CSS,
JS.
В задачах должна быть возможность вставки фрагментов кода и изображений.
Текстовый редактор Tiptap должен быть в функционале создания и редактирования уроков на странице администрирования (админ-панели). 
Всё должно быть просто и минимально.

Описание админ-панели
Админ-панель должна быть на отдельной странице по адресу: <url сайта>/bod. Вход в админ панель должен быть с формой авторизации со следующими данными:
Логин: bodryakov 
Пароль: bod
Вход в админ-панель должен быть только по URL. Кнопки входа на страницах сайта быть не должно.
Обеспечь защиту от XSS/CSRF атак.
Админ и редактор уроков должен быть только один, добавление других админов не нужно.
В Админ-панели должно быть предусмотрено добавление и удаление разделов и уроков, а также редактирование заголовков разделов и уроков. Удаление, добавление и редактирование должно обеспечиваться соответствующими кнопками с соответствующими иконками и всплывающими подсказками.
При удалении, модальное окно подтверждения не нужно.
В момент сохранения названий разделов и уроков должна быть валидация:
Поле названия раздела заполнено и название не повторяется
Поле slug заполнено и slug не повторяется. Slug должен быть только маленькими английскими буквами и дефисы, пробелы запрещены.
Порядковый номер заполнен и не повторяется.
В Админ-панели должно быть предусмотрено создание страниц уроков и текстов уроков, тестов, задач с помощью полнофункционального редактора текста Tiptap. 
В интерфейсе создания тестов должны быть отдельные поля для вопроса, 4 вариантов ответов и checkbox для отметки правильного ответа.
Должна быть возможность добавлять изображения. Изображения могут добавляться как в текст теории, так и в текст задач. Изображения должны загружаться через стандартное диалоговое окно выбора файла. Реализовывать интерфейс drag and drop для загрузки файлов не нужно. Изображения должны сохраняться в формате JSONB в базе данных Supabase. При удалении урока изображения тоже должны удаляться из базы данных Supabase.
При создании и редактировании урока должна быть кнопка “сохранить черновик”, которая сохраняет данные урока, но не публикует их, а также кнопка “опубликовать”, которая публикует урок в открытый доступ.
После редактирования информации в админ-панели все изменения должны сохранятся в соответствующих записях базы данных Supabase в формате JSON. 

Описание BackEnd
Должен быть функционал запросов с FastAPI на Supabase на создание, изменение, удаление JSONB данных разделов и уроков (Полные RESTful API CRUD операции).
При выборе пользователем урока должна формироваться HTML-страница соответствующего урока.
Изображения должны храниться в Supabase Storage.

Описание дизайна
Должны быть хлебные крошки вида Раздел-<номер_раздела>-<название_раздела>/Урок-<номер_урока>-<название_урока>.
Хлебные крошки должны быть кликабельны.
Дизайн web-приложения должен быть минималистичный, адаптивный, выполненный в плоском дизайне material design.
Должна быть адаптивность, со следующими значениями точек перелома:
Минимальная ширина: 320px
далее точки перелома:
< 600px
≥ 900px
≥ 1200px
≥ 1600px
≥ 1920px

Адаптивность должна быть сделана с использованием самых новейших возможностей CSS.
Используй следующую заготовку для media-запросов:

/* Базовые стили для мобильных устройств (от 320px) 
   Всё, что ниже 600px, описывается здесь без медиа-запроса */

/* Малые устройства (например, крупные смартфоны или маленькие планшеты) */
@media (width >= 600px) {
    /* Стили для экранов от 600px до 899px */
}

/* Средние устройства (планшеты в альбомной ориентации) */
@media (width >= 900px) {
    /* Стили для экранов от 900px до 1199px */
}

/* Ноутбуки и небольшие десктопы */
@media (width >= 1200px) {
    /* Стили для экранов от 1200px до 1599px */
}

/* Большие мониторы */
@media (width >= 1600px) {
    /* Стили для экранов от 1600px до 1919px */
}

/* Сверхширокие мониторы (Full HD и выше) */
@media (width >= 1920px) {
    /* Стили для экранов от 1920px и выше */
}

Вверху всех страниц сайта должна быть узкая (минимальной высоты) полоса header-а.
Должно быть переключением светлой и тёмной темы с кнопкой в header-е справа. 
Цвета предпочтительны серые, голубые, синие. Базовая тема светлая.
Должен использоваться чистый, самый современный на 2026 год, CSS. 
Без поддержки старых браузеров. 
Вместо Flex используй Grid. 
Промотка должна быть плавная. 

Правила для синтакиса JavaScript файлов.


Инструкции для TRAE.
Для уточнения требований и параметров web-приложения - задай мне дополнительные вопросы.

После получения ответа на все вопросы - сначала создай структуру проекта, всех файлов и каталогов, и предложи мне на утверждение.
После создания структуры проекта, сделай текстовое описание проекта, с общим описанием проекта, описанием различных особенностей и тонкостей, описанием структуры базы данных, описанием того, как ты будешь создавать проект.
Только после утверждения структуры и согласования всех параметров - начинай создавать приложение.

После начала создания приложения следуй следующей последовательности:
1. Создай SQL-скрипт создания таблиц базы данных для этого проекта для запуска в Supabse.
2. Создай SQL-скрипт заполнения таблиц первичными тестовыми данными (на тему основ фреймворка FastAPI) (включая теоретический материал, тестовые вопросы, задачи (только 2 раздела по 2 урока)).
3. создай виртуальное окружение.
4. создай файл requirements.txt с необходимыми зависимостями с учётом деплоя приложения на koyeb.com.
5. установи необходимые зависимости.
6. для настройки деплоя на koyeb.com создай файл Procfile с командой запуска приложения
7. Генерируй код приложения распределяя его в необходимые файлы и каталоги.
(необходимые файлы и каталоги создавай автоматически, не задавая мне вопросов подтверждения, а также вноси в них изменения автоматически, не задавая мне вопросов подтверждения)

В каждый файл нужно добавлять комментарии на русском языке, в частности: в начало самого файла, с описанием назначения и функционала файла, комментарии к каждому импорту, комментарии к каждому существенному блоку кода, функции, циклу, условию, и т.п. .
